## Context: Core proposed system for the research plan. Method: We propose a novel Broad Incremental Detection (BID) framework that combines the efficiency of Broad Learning Systems (BLS) with incremental learning capabilities for dynamic Android malware detection.

### Support

The strongest support for the proposed Broad Incremental Detection framework comes from [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36), which directly demonstrates that a broad-learning-based Android malware detector can be lightweight, static-feature driven, and incrementally updatable. That work uses a 379-dimensional binary feature vector from API calls, intent actions, and permissions, a three-layer broad learning network with feature and enhancement layers, sparse autoencoders, hierarchical feature transformations, and incremental retraining, and reports an average scan time of about 0.2 seconds. This is highly relevant to the proposed BID plan because it supports the central hypothesis that broad learning can provide efficient Android malware detection while incremental updates can adapt to new malware without full system rebuilding, and it provides a concrete precedent for the proposed Sparse Relational Autoencoder and pseudo-inverse-based dynamic weight updates. A second, more indirect line of support comes from [(Yuan et al., 2016-02)](https://www.semanticscholar.org/paper/bfbdf36d50066c39dedf688150d63ba4b84d7e52), which evaluates a deep learning detector on 20,000 benign apps and 1,760 malicious apps from Contagio and Genome, and shows that machine-learning-based detection is less vulnerable to repackaging than signature-based anti-virus products. That paper reports 96.60% detection accuracy at a 1:1 malicious-to-benign ratio with 500 samples per class, and shows that most commercial anti-virus products drop sharply after repackaging, with six below 10% and eight below 35% on 50 repackaged Contagio apps. This supports the BID motivation that adaptive, data-driven detection is needed for evolving malware variants, even though the work itself is not incremental and does not use broad learning. A third, more indirect support comes from [(Chen et al., 2019-04)](https://www.semanticscholar.org/paper/da1500380c9f5229f3a18aa14eea13e8981f8ef7), which shows that static Android malware detection can be improved by learned feature representations. DroidVecDeep extracts permissions, actions, and sensitive API calls, selects features with random forests, converts app feature documents into word2vec vectors with min_count=1, and trains a Deep Belief Network with greedy layer-wise pretraining and fine-tuning. On a 15,000-app dataset reduced to 3,000 balanced samples, it reports 99.1% accuracy, compared with 93.37% for Drebin and 97.6% for DroidDeep, and identifies a best DBN configuration of two hidden layers with 200 nodes per layer achieving 97.29% precision. This supports the BID plan by showing that static feature representation learning is a viable route for Android malware detection, but it also positions BID as a potentially more efficient incremental alternative to full deep-model training.

### Contradictions

The strongest contradiction, or more precisely the strongest evidential weakness, is that [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36) does not report accuracy, precision, recall, F1-score, statistical significance, dataset sizes, hardware specifications, hyperparameters, or exact training and test splits for BL-AMD. It only reports an average scan time of about 0.2 seconds and qualitative improved performance against MalGAN through incremental retraining. This limits the strength of the evidence for the proposed BID framework because the research plan requires demonstrating both high detection accuracy and computational efficiency, especially across TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020, and the related work does not provide the quantitative detection metrics needed to confirm that broad learning plus incremental updates outperforms deep learning baselines. A second contradiction comes from [(Chen et al., 2019-04)](https://www.semanticscholar.org/paper/da1500380c9f5229f3a18aa14eea13e8981f8ef7), which shows that a non-incremental deep static pipeline can achieve very high accuracy without the proposed BLS pseudo-inverse update mechanism. DroidVecDeep uses full DBN training, random forest feature selection, word2vec representation learning, and 10-fold cross-validation on 3,000 balanced samples, and reports 99.1% accuracy. This challenges the necessity of incremental broad learning for accuracy, because a conventional deep model can already perform strongly on static Android malware features. It also uses a balanced 1:1 malicious-to-benign subset from a larger imbalanced collection, which may overstate real-world performance and weaken the generalizability of the result to the highly imbalanced datasets planned for BID. A weaker contradiction comes from [(Yuan et al., 2016-02)](https://www.semanticscholar.org/paper/bfbdf36d50066c39dedf688150d63ba4b84d7e52), where malicious-class precision and recall fluctuated under lopsided training ratios because the malicious test sets were small, and the repackaging evaluation was limited to 50 Contagio apps from 2014 with unknown commercial anti-virus training data. This does not directly contradict BID, but it warns that apparent gains from adaptive or data-driven detection may be unstable when malicious samples are scarce, and it limits the strength of the evidence that incremental learning will reliably improve robustness to repackaged or variant malware.

### Suggested Action

The most important action is to make the BID evaluation quantitatively rigorous and directly comparable to the related work by reporting accuracy, precision, recall, F1-score, AUC where appropriate, 95% confidence intervals, statistical significance, and per-class results for both binary and multiclass tasks on TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020, using the planned 70% training and 30% testing split and the 5:3:2 incremental split. The experiments should explicitly compare initial training time plus incremental update time against full retraining time, and should report hardware specifications, batch size, epochs, feature dimensions, and update latency so that the claimed efficiency of pseudo-inverse-based BLS updates can be validated against the 0.2-second scan target implied by [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36). The next most important action is to strengthen the baseline suite by adding representation-learning and deep static baselines inspired by [(Chen et al., 2019-04)](https://www.semanticscholar.org/paper/da1500380c9f5229f3a18aa14eea13e8981f8ef7), such as a word2vec plus DBN pipeline, random forest feature selection, and Drebin- or DroidDeep-style static baselines if feasible, in addition to the planned SVM with RBF kernel, Naive Bayesian with polynomial model, DeepAMD, BiGRU, and RNN-LSTM with 50 epochs and batch size 64. This will isolate whether the proposed Sparse Relational Autoencoder contributes beyond standard sparse autoencoders, word2vec, or one-hot static features. A further important action is to add robustness experiments for repackaging, variant malware, and adversarial attacks, following the repackaging protocol in [(Yuan et al., 2016-02)](https://www.semanticscholar.org/paper/bfbdf36d50066c39dedf688150d63ba4b84d7e52) and the MalGAN evaluation in [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36), with class-wise metrics rather than only overall accuracy. The plan should also explicitly address class imbalance and small malicious-class evaluation by testing malicious-to-benign ratios such as 1:1, 1:5, 1:10, and 1:20, and by reporting malicious precision and recall separately, because [(Yuan et al., 2016-02)](https://www.semanticscholar.org/paper/bfbdf36d50066c39dedf688150d63ba4b84d7e52) shows that overall accuracy can rise under benign-heavy conditions while malicious-class performance remains unstable. Finally, the incremental learning mechanism should be specified in greater implementation detail, including the partitioned pseudo-inverse update equations, numerical stability safeguards, memory footprint, update frequency, and whether previously learned weights are frozen or adjusted, so that the claimed advantage over full retraining is reproducible and not merely conceptual.

## Context: Central adaptation mechanism that avoids complete retraining when new malware appears. Method: Our incremental learning mechanism leverages the pseudo-inverse calculation properties of BLS to enable dynamic weight updates when new malware samples arrive. Rather than retraining the entire model, we update the system by calculating the pseudo-inverse of partitioned matrices, allowing for efficient incorporation of new data while preserving previously learned knowledge.

### Support

The strongest support for the proposed BID adaptation mechanism comes from [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36), which directly uses a broad learning system for on-device Android malware detection with 379 binary API-call, intent-action, and permission features, a three-layer feature/enhancement/output architecture, one-shot parameter computation, sparse autoencoders, hierarchical feature transformations, and incremental learning without rebuilding the detector. This is the closest prior evidence that BLS-style one-shot or incremental updates can be lightweight and relevant to the proposed SRAE-enhanced BLS, although it does not specify pseudo-inverse partitioned matrix updates. Read as an iterative line of work, this BLS-based detector extends earlier online-adaptation ideas into a lightweight static-feature setting and therefore supports the core BID hypothesis that broad learning can be adapted to new malware without full retraining. The next strongest support is the longitudinal evaluation of DroidEvolver in [(Mesbah et al., unknown_d)](https://www.semanticscholar.org/paper/3e965c0b9b0e37349b17743569b5628085de1f00), where an API-call-based static detector with continual feature-set updates was trained on 140,000 apps from 2013 to 2018 and tested on 40,000 apps from 2019 to 2022, achieving F1 of 94.40% in 2019 and 87.56% in 2020. This shows that non-retraining adaptation can remain competitive in a large 200,000-app Android setting, but the later decline below 80% in 2021 indicates that support is conditional on the stability of the feature space and classifier over time. Older and less direct support comes from [(Narayanan et al., 2017-05)](https://www.semanticscholar.org/paper/1bee62e1faacc87a97b49a9b241cf81eed5d0b73), whose CASANDRA online learning component updates a static graph/kernel classifier without complete retraining, and from [(Xu et al., 2019-06)](https://www.semanticscholar.org/paper/c41b3b09c425773386ca8633ba786c2548b29b4b), whose DroidEvolver model pool uses AROW and RDA for online model construction and evolvement. These works establish the broader scientific trajectory that Android malware detectors can be adapted online, but they do not provide direct evidence for BLS pseudo-inverse partitioned matrix updates or for the specific computational advantage claimed by BID.

### Contradictions

The strongest contradiction to the proposed method is the quantitative longitudinal degradation reported for DroidEvolver in [(Mesbah et al., unknown_d)](https://www.semanticscholar.org/paper/3e965c0b9b0e37349b17743569b5628085de1f00): its F1 fell from 94.40% in 2019 to 87.56% in 2020 and below 80% in 2021, while LongCGDroid recorded 81.48%, despite continual feature-set updates and a 200,000-app protocol. This contradicts the assumption that a single incremental update mechanism, including BID's pseudo-inverse BLS update, will automatically preserve previously learned knowledge over multi-year malware evolution; it suggests that drift, feature obsolescence, or model aging can erode performance unless the method includes drift detection, model replacement, feature evolution, or model-pool selection. The next contradiction is evidential weakness in [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36): although it claims improved robustness and better performance through incremental retraining, it reports only about 0.2-second average scanning time and no accuracy, precision, recall, F1, confusion matrix, dataset size, hardware, hyperparameters, or baseline comparison, so it cannot substantiate the proposed claim that pseudo-inverse partitioned matrix updates improve detection while reducing retraining cost. Weaker contradictions and limitations arise from [(Narayanan et al., 2017-05)](https://www.semanticscholar.org/paper/1bee62e1faacc87a97b49a9b241cf81eed5d0b73) and [(Xu et al., 2019-06)](https://www.semanticscholar.org/paper/c41b3b09c425773386ca8633ba786c2548b29b4b), which describe online adaptation and model-pool evolvement but provide no numerical accuracy, update time, statistical significance, or implementation details in the supplied excerpts. This leaves open whether their online mechanisms are computationally or statistically superior to full retraining, and the DroidEvolver model-pool design implied by [(Xu et al., 2019-06)](https://www.semanticscholar.org/paper/c41b3b09c425773386ca8633ba786c2548b29b4b) suggests that a single pseudo-inverse-updated BLS model may be insufficient compared with maintaining and selecting among multiple online models.

### Suggested Action

Most important, BID should add a longitudinal incremental evaluation that mirrors the 2013-2018 train and 2019-2022 test protocol used by [(Mesbah et al., unknown_d)](https://www.semanticscholar.org/paper/3e965c0b9b0e37349b17743569b5628085de1f00), reporting TPR, FPR, F1, update time, and statistical significance per year, and explicitly test whether pseudo-inverse partitioned matrix updates outperform full retraining and DroidEvolver-style continual feature updates over multiple drift periods. Second, the method should specify and benchmark the pseudo-inverse partitioned matrix update at the implementation level, including matrix partitioning, numerical stability, regularization, memory footprint, update latency, and comparison against full BLS retraining on TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020, including the planned 5:3:2 split and a 70/30 baseline. Third, the SRAE should be validated against the sparse autoencoder and hierarchical feature transformations used in [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36), with ablations for reconstruction loss, relationship reconstruction loss, and sparsity, and with on-device or resource-constrained latency and memory measurements to support the lightweight claim. Finally, BID should incorporate or compare against the online model-pool and averaging baselines suggested by [(Xu et al., 2019-06)](https://www.semanticscholar.org/paper/c41b3b09c425773386ca8633ba786c2548b29b4b) and the kernel-based online adaptation of [(Narayanan et al., 2017-05)](https://www.semanticscholar.org/paper/1bee62e1faacc87a97b49a9b241cf81eed5d0b73), including AROW/RDA, drift and aging analysis, and adversarial robustness, to show that the proposed single-model BLS update is not only faster than retraining but also more stable under evolving malware.

## Context: Base network architecture underlying the BID detector. Method: Our approach builds upon the Random Vector Functional Link Neural Network (RVFLNN) architecture, utilizing a single-layer structural neural network with feature nodes and enhancement nodes.

### Support

The strongest support for the proposed RVFLNN-based base architecture comes from [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36), which implements BL-AMD, a broad-learning Android malware detector using a three-layer network whose first two layers are feature and enhanced data-processing units and whose output combines them for malicious/benign probabilities. This is directly analogous to the proposed single-layer RVFLNN/BLS design with feature nodes and enhancement nodes, and it reports on-device scanning in about 0.2 seconds, one-shot broad-learning parameter computation, sparse autoencoder and hierarchical feature transformations, and incremental retraining on-device, all of which support the plan's goal of a lightweight, rapidly adaptable Android detector. The second, weaker support comes from [(Pendlebury et al., 2018-07)](https://www.semanticscholar.org/paper/7ab5a2b7d2caa8969c06e1f24dfda2a6f5c654f6), which does not implement RVFLNN, BLS, SRAE, or pseudo-inverse updates but validates the broader research context by showing that Android malware classifiers must be evaluated under temporal decay and incremental-retraining settings; its use of timestamped AndroZoo apps, VirusTotal thresholds, 10 percent malware ratio, monthly test slots, AUT(F1,24m), and baselines including linear SVM, Random Forest, and a deep network supports the plan's need for realistic incremental evaluation and baseline comparisons, especially SVM and deep learning baselines. Read iteratively, Pendlebury establishes the temporal evaluation standard, while Selvaganapathy extends the problem to broad-learning on-device detection but leaves that standard unmet.

### Contradictions

The strongest contradiction to the proposed method as currently framed is that [(Pendlebury et al., 2018-07)](https://www.semanticscholar.org/paper/7ab5a2b7d2caa8969c06e1f24dfda2a6f5c654f6) shows realistic temporal performance is much lower than biased 10-fold estimates, with AUT(F1,24m) of 0.58 for linear SVM, 0.32 for Random Forest, and 0.64 for a deep network, and that incremental retraining or rejection must be analyzed as performance-cost tradeoffs involving labeling and quarantine costs. This contradicts the plan's simpler 70 percent train / 30 percent test and 5:3:2 incremental split as sufficient evidence that BID will improve in real-world deployment, because it does not model time decay, monthly drift, class-ratio tuning, or operational costs. A weaker but important limitation is that [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36) provides only a 0.2 second average scan time and a qualitative claim of better performance against MalGAN through incremental retraining, without accuracy, precision, recall, F1, false positive/negative rates, baseline comparisons, dataset size, malware families, train-test split, hardware, incremental sample count, or statistical significance. Therefore it cannot substantiate the plan's expectation that an RVFLNN/BLS detector will achieve high detection accuracy, robustness, or measurable incremental gains, and it does not provide evidence that the proposed SRAE or partitioned pseudo-inverse update mechanism is superior to complete retraining or other incremental baselines.

### Suggested Action

The most important action is to replace or supplement the 70/30 and 5:3:2 experiments with the temporal evaluation protocol from [(Pendlebury et al., 2018-07)](https://www.semanticscholar.org/paper/7ab5a2b7d2caa8969c06e1f24dfda2a6f5c654f6): use timestamped Android apps, define goodware and malware with explicit VirusTotal thresholds, exclude grayware, match training and testing malware ratios such as 10 percent, train on an earlier year and test monthly over later months, compute AUT(F1,24m) or equivalent time-integrated F1, and compare no retraining, tuned training ratio, BID pseudo-inverse incremental updates, and rejection/quarantine while reporting labeling and quarantine costs. Second, add the missing quantitative evaluation required by the plan and by the limitations of [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36): report accuracy, precision, recall, F1, FPR, FNR, AUC, confidence intervals, and statistical significance against SVM with RBF kernel, Naive Bayes, DeepAMD, BiGRU, RNN-LSTM, and also linear SVM, Random Forest, and deep static-feature baselines, with consistent 50 epochs and batch size 64 for deep models. Third, specify the RVFLNN/BID implementation in enough detail to test the claimed mechanism: number and type of feature nodes and enhancement nodes, random weight distributions, SRAE architecture and loss terms, partitioned pseudo-inverse update equations, incremental batch size, update frequency, stability/plasticity or catastrophic forgetting metrics, and adversarial evaluation with MalGAN. Finally, report on-device or constrained hardware specifications, model size, memory, energy, and inference latency, using the 0.2 second scan time from [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36) as a benchmark rather than a validated target.

## Context: Training objective for the SRAE feature generator. Method: The SRAE minimizes a composite loss function that balances data reconstruction loss, relationship reconstruction loss, and regularization terms.

### Support

The strongest support for the SRAE composite loss comes from [(Gopakumar et al., 2016-09)](https://www.semanticscholar.org/paper/1b53a99633f5f1486e8c37d14d0a13e8c1948bc9), which used an autoencoder-derived penalty and a feature-graph Laplacian penalty to regularize a lasso logistic regression model for 6-month heart-failure readmission. In that work, the augmented autoencoder-graph model achieved the best reported AUC of 0.65 with 20 hidden units, alpha=0.005, lambda_AE=3000, lambda_graph=0.3, and lambda_en=0.03, and it produced the most stable feature selection: at a 95% confidence interval, autoencoder-regularized models identified all 50 top features as stable, compared with 3 for pure lasso, 21 for elastic net, and 24 for graph regularization. This is directly relevant to the BID plan because it shows that adding an autoencoder reconstruction/regularization objective and a relational/graph penalty can improve sparse feature selection and weight stability, which is the intended role of the SRAE feature generator before BLS pseudo-inverse updates. Read iteratively, this newer quantitative result extends the older regularization principle in [(Hinton, 1989-09)](https://www.semanticscholar.org/paper/a57c6d627ffc667ae3547073876c35d6420accff) by showing that an autoencoder-derived penalty can stabilize sparse feature selection, although it uses a feature-graph rather than sample-relationship reconstruction. The next strongest support is from [(Japkowicz et al., 1995-08)](https://www.semanticscholar.org/paper/22c0bf46726ad1c90b5fac7f16638c813e86c829), whose HIPPO autoencoder uses reconstruction error on positive instances and a threshold component to separate positives from negatives, demonstrating that reconstruction error can serve as a representation and discrimination signal even with limited negative examples; however, the excerpt provides no numeric error rates, and the method lacks relationship reconstruction, sparse relational modeling, and BLS integration. [(Hinton, 1989-09)](https://www.semanticscholar.org/paper/a57c6d627ffc667ae3547073876c35d6420accff) provides foundational support for the regularization terms in the SRAE loss by showing that squared-weight decay can improve generalization, prevent table-lookup behavior, and reduce sensitivity to zero-mean uncorrelated input noise in a linear network, although it reports no quantitative malware or autoencoder outcomes. [(Chalapathy et al., 2017-04)](https://www.semanticscholar.org/paper/1d4ec24a6da3be62dc5d7efbae2a101c63f187e8) supports the use of reconstruction plus robust regularization for anomaly detection, using a robust convolutional autoencoder with batch normalization, ELU activations, and grid-searched regularization, but the excerpt gives no numeric AUPRC, AUROC, P@10, or MSE values and is limited to image datasets. Finally, [(Ruff et al., 2020-09)](https://www.semanticscholar.org/paper/30b99ae0682d42a2010be401dd1d8f7baca9bb5f) supports the broader reconstruction-error paradigm for anomaly detection on MVTec-AD, but the supplied excerpt does not provide numeric AUC values and does not test relationship reconstruction or BLS feature generation.

### Contradictions

The strongest indirect contradiction is also from [(Gopakumar et al., 2016-09)](https://www.semanticscholar.org/paper/1b53a99633f5f1486e8c37d14d0a13e8c1948bc9): although autoencoder-graph regularization improved feature stability, the best AUC was only 0.65, and the best configuration required a large autoencoder penalty lambda_AE=3000, indicating that such composite objectives can be hyperparameter-sensitive and may not translate into strong predictive accuracy. Moreover, the graph penalty was a feature-graph Laplacian, not a sample-relationship reconstruction term, so the result does not validate the SRAE relationship reconstruction loss for Android malware or BLS feature generation. This newer result also qualifies the older general regularization claim in [(Hinton, 1989-09)](https://www.semanticscholar.org/paper/a57c6d627ffc667ae3547073876c35d6420accff) by showing that autoencoder regularization can improve stability without necessarily delivering high AUC. The next strongest limitation is from [(Chalapathy et al., 2017-04)](https://www.semanticscholar.org/paper/1d4ec24a6da3be62dc5d7efbae2a101c63f187e8), where the inductive CIFAR-10 setting, trained on 5000 dog images and tested on 500 dogs plus 50 cats, was reported to have lower table values than the single-dataset task, suggesting that reconstruction-based anomaly detection can degrade when generalizing to unseen classes, a risk analogous to detecting new malware variants; the excerpt also lacks numeric AUPRC, AUROC, and P@10 values and does not include relational reconstruction. [(Ruff et al., 2020-09)](https://www.semanticscholar.org/paper/30b99ae0682d42a2010be401dd1d8f7baca9bb5f) provides a reconstruction-based anomaly-detection context on MVTec-AD but no numeric AUC values in the excerpt, so it does not provide evidence that adding relationship reconstruction improves detection over standard reconstruction error. [(Japkowicz et al., 1995-08)](https://www.semanticscholar.org/paper/22c0bf46726ad1c90b5fac7f16638c813e86c829) contradicts the proposed method only by omission: HIPPO relies on positive-only autoencoder reconstruction and thresholding, with fixed learning rate 0.05, momentum 0.9, hidden units 32, 153, or 20, and five-fold cross-validation, but it does not test relationship reconstruction, sparse relational structure, or incremental BLS updates, and the excerpt contains no numeric error rates. Finally, [(Hinton, 1989-09)](https://www.semanticscholar.org/paper/a57c6d627ffc667ae3547073876c35d6420accff) supports only a simple squared-weight penalty and provides no evidence for relationship reconstruction or for the composite SRAE objective in malware detection.

### Suggested Action

The most important action is to make the SRAE composite loss empirically falsifiable by running component ablations on the planned Android datasets: data reconstruction only, data reconstruction plus relationship reconstruction, and full SRAE with regularization, evaluated on TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020 using the planned 70/30 and 5:3:2 splits, with accuracy, precision, recall, F1, AUPRC, AUROC, P@10, computational time, and incremental update time. Second, adopt the stability evaluation used by [(Gopakumar et al., 2016-09)](https://www.semanticscholar.org/paper/1b53a99633f5f1486e8c37d14d0a13e8c1948bc9), including 95% confidence-interval feature-selection stability and signal-to-noise ratio of top feature weights, and compare SRAE features against lasso, elastic net, graph-regularized, and standard sparse autoencoder baselines while reporting grid-searched hyperparameters such as lambda_AE, lambda_rel, alpha, hidden units, and learning rate. Third, incorporate a robust reconstruction or robust regularization term inspired by [(Chalapathy et al., 2017-04)](https://www.semanticscholar.org/paper/1d4ec24a6da3be62dc5d7efbae2a101c63f187e8) to reduce sensitivity to noisy or malicious samples, and report AUPRC, AUROC, and P@10 on the imbalanced CIC-InvesAndMal-2019 and large CCCS-CIC-AndMal-2020 datasets. Fourth, include [(Hinton, 1989-09)](https://www.semanticscholar.org/paper/a57c6d627ffc667ae3547073876c35d6420accff) weight decay as a simple regularization baseline and compare it with the SRAE relational and sparse regularization terms to isolate the contribution of relationship reconstruction. Fifth, use the reconstruction-error threshold idea from [(Japkowicz et al., 1995-08)](https://www.semanticscholar.org/paper/22c0bf46726ad1c90b5fac7f16638c813e86c829) as an auxiliary diagnostic or incremental trigger, but ensure the primary evaluation still measures whether initial training plus BLS pseudo-inverse updates is faster than complete retraining and whether performance improves on new malware. Finally, report reproducibility details missing from the related work, including dataset splits, hardware, epochs, batch size, hidden units, learning rate, momentum, dropout, random seeds, and statistical significance tests across folds.

## Context: Empirical evaluation data covering different Android malware feature spaces and class structures. Method: We will evaluate our BID framework across three comprehensive datasets: TUANDROMD (containing 1,000 benign and 24,553 malware samples with 214 permissions and 27 API calls), CIC-InvesAndMal-2019 (1,187 benign and 407 malware samples with 8,115 features), and CCCS-CIC-AndMal-2020 (162,181 benign and 195,624 malware samples with 9,502 features covering 14 malware categories).

### Support

The strongest support for the proposed BID evaluation is the systematic benchmarking evidence in [(Liu et al., 2024-02)](https://www.semanticscholar.org/paper/288d9b280299e1a7a88b0bb751c17c6c8fad50c5), which re-implements 12 ML Android malware detectors across 10 APK features, 4 feature representations, and 8 ML models on a primary set of 221,310 apps containing 22,870 malicious and 198,440 benign apps and an additional 2021-2024 set of 7,911 apps containing 791 malicious and 7,120 benign apps, showing that detector performance depends on feature choice, class ratio, and malware evolution; this directly supports the plan's multi-dataset evaluation of TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020 and its binary and multiclass tasks. A second strong support is [(Polatidis et al., 2024-07)](https://www.semanticscholar.org/paper/ddde487f29910e0a91f2d8d055f002e9c1f4f9c2), which uses the same CCCS-CIC-AndMal 2020 dataset and shows that high-dimensional Android malware feature spaces can be reduced from 489 KronoDroid features to 28, 19, and 27 features for Airpush, BankBot, and SMS, making simple decision-tree and random-forest classifiers interpretable and accurate; this supports the plan's use of 9,502-feature CCCS-CIC-AndMal-2020 and the SRAE's feature-selection and relational-representation role. Computational-efficiency support comes from [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3), where MAPAS classified 2,000 apps in 21.18 seconds on one core at 1.059 milliseconds per app and used far less memory than CNN and MaMaDroid baselines, while the CNN used 10,590 MiB of GPU memory and about 2,070 MB of RAM and had an 11 percent lower detection rate than MAPAS; this supports the plan's emphasis on lightweight BLS/RVFLNN and incremental pseudo-inverse updates rather than expensive deep retraining. Large-scale deep-learning support is provided by [(Vanjire, and Lakshmi, 2024-06)](https://www.semanticscholar.org/paper/213527d0fcbe381a81ab377f72b3b150a33ea81e), whose raw-byte CNN achieved AUC 0.9953 on 833,000 samples and 0.9920 after duplicate removal, with 26 minutes of training and testing on one GPU, indicating that deep baselines such as DeepAMD, BiGRU, and RNN-LSTM can be evaluated at scale but also that duplicate handling matters. Permissions-based support is weaker but relevant in [(Zaidi et al., 2023-11)](https://www.semanticscholar.org/paper/5b180790aec6046bbce5137cfdcee70f27dcf59b), where KNN, logistic regression, and random forest on permissions achieved F1 scores of 86.72 percent, 85.05 percent, and 86.91 percent, supporting TUANDROMD's 214 permissions as a meaningful feature space. The weakest support is [(Sharmeen et al., 2019-09)](https://www.semanticscholar.org/paper/ba1b0011a69cae575f4fe0cf92592f502a744508), whose k-means distance-augmented deep model qualitatively outperformed a supervised deep baseline on 8,119 malware and 10,000 benign samples, suggesting unsupervised relational or cluster features can help, but it provides no numerical metrics, incremental protocol, or BLS/SRAE evidence.

### Contradictions

The strongest contradiction is that the most rigorous benchmarking evidence, [(Liu et al., 2024-02)](https://www.semanticscholar.org/paper/288d9b280299e1a7a88b0bb751c17c6c8fad50c5), finds current ML detectors face open challenges under limited data, rapid malware evolution, and adversarial attacks, and uses temporal yearly AndroZoo sub-datasets with 9:1 goodware-to-malware ratios and duplicate avoidance; this contradicts the proposed plan's reliance on a standard 70/30 split and a 5:3:2 incremental split that may not simulate temporal evolution, class-ratio shifts, or duplicate leakage. A second important contradiction is that [(Polatidis et al., 2024-07)](https://www.semanticscholar.org/paper/ddde487f29910e0a91f2d8d055f002e9c1f4f9c2) shows simple default scikit-learn decision-tree and random-forest classifiers on reduced binary features can identify malware with very high accuracy on CCCS-CIC-AndMal 2020 and KronoDroid, which challenges whether the added complexity of BLS, SRAE, and pseudo-inverse updates is necessary unless BID clearly improves incremental update time, multiclass recall, or robustness. Third, [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) contradicts the assumption that incremental deep learning is automatically needed for efficiency: MAPAS, a non-incremental Jaccard and API-graph detector, achieved 1.059 milliseconds per app on one core and much lower memory than CNN, while MaMaDroid random forest was the best accuracy baseline and MAPAS was about 3 percent lower, so BID must beat simple static baselines on both detection and update cost. Fourth, [(Zaidi et al., 2023-11)](https://www.semanticscholar.org/paper/5b180790aec6046bbce5137cfdcee70f27dcf59b) shows permissions-based classifiers can have high precision but recall around 77 to 78 percent, contradicting any claim that high accuracy alone is sufficient; BID must improve recall on TUANDROMD and other datasets, especially for minority malware classes. Fifth, [(Vanjire, and Lakshmi, 2024-06)](https://www.semanticscholar.org/paper/213527d0fcbe381a81ab377f72b3b150a33ea81e) reports AUC dropping from 0.9953 to 0.9920 after duplicate raw-byte removal, contradicting the assumption that large-scale high AUC is robust without duplicate and hash-busting controls; the proposed 70/30 and 5:3:2 splits need duplicate-aware validation. The weakest contradiction is [(Sharmeen et al., 2019-09)](https://www.semanticscholar.org/paper/ba1b0011a69cae575f4fe0cf92592f502a744508), which provides only qualitative claims of higher accuracy and F1 without numerical values, hardware, epochs, or split ratios, so it cannot substantiate the proposed method's quantitative efficiency or incremental claims.

### Suggested Action

The most important action is to redesign the incremental evaluation to match the evolution evidence in [(Liu et al., 2024-02)](https://www.semanticscholar.org/paper/288d9b280299e1a7a88b0bb751c17c6c8fad50c5): in addition to the planned 5:3:2 ratio, use temporal yearly or first-seen splits on TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020, avoid duplicate APKs across training, testing, and incremental sets, report class-ratio changes, and compare BID's initial training plus pseudo-inverse update time against full retraining on identical hardware with wall-clock, memory, and per-app inference metrics. Second, add the strongest non-incremental baselines implied by the related work: default scikit-learn random forest and decision tree with the feature-reduction and binarization pipeline from [(Polatidis et al., 2024-07)](https://www.semanticscholar.org/paper/ddde487f29910e0a91f2d8d055f002e9c1f4f9c2) on CCCS-CIC-AndMal 2020, permissions-based KNN, logistic regression, and random forest from [(Zaidi et al., 2023-11)](https://www.semanticscholar.org/paper/5b180790aec6046bbce5137cfdcee70f27dcf59b) for TUANDROMD, and API-call, Markov-chain, or Jaccard-style baselines inspired by [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) where API features are available. Third, implement duplicate removal, hash-busting checks, and sanity checks before the 70/30 and 5:3:2 splits, following [(Vanjire, and Lakshmi, 2024-06)](https://www.semanticscholar.org/paper/213527d0fcbe381a81ab377f72b3b150a33ea81e), and report AUC, per-class precision, recall, and F1, macro and micro F1 for the 14 CCCS-CIC categories, ROC-AUC, and statistical significance or confidence intervals. Fourth, ablate SRAE against random RVFLNN, standard sparse autoencoder, and no relational loss, and report feature-selection behavior on the 8,115-feature CIC-InvesAndMal-2019 and 9,502-feature CCCS-CIC-AndMal-2020 spaces, because [(Polatidis et al., 2024-07)](https://www.semanticscholar.org/paper/ddde487f29910e0a91f2d8d055f002e9c1f4f9c2) shows high-dimensional feature spaces can be reduced to small interpretable subsets. Fifth, include unlabelled or cluster-distance features only as an optional ablation, since [(Sharmeen et al., 2019-09)](https://www.semanticscholar.org/paper/ba1b0011a69cae575f4fe0cf92592f502a744508) suggests unsupervised distance features may help but lacks quantitative evidence; this should not replace the proposed SRAE relational objective. Finally, report computational resources, CPU or GPU, RAM, epochs, batch size, and hyperparameters for all baselines, including the planned 50 epochs and batch size 64 for deep models, to make the claimed efficiency of BLS pseudo-inverse updates reproducible.

## Context: Comparative evaluation against established malware detection methods. Method: For baseline comparisons, we will implement and evaluate against established methods including SVM with RBF kernel, Naive Bayesian with polynomial model, and deep learning approaches (DeepAMD, BiGRU, and RNN-LSTM). All deep learning models will use consistent parameters (50 epochs, batch size 64) to ensure fair comparison.

### Support

The strongest support comes from [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3), which directly operationalizes the proposed baseline-comparison method by comparing an established API-call-graph detector, MaMaDroid, with a CNN classifier and MAPAS on 18,000 applications (9,000 malicious and 9,000 benign), 21,690 unique API call graphs, and a 2,000-application test set, while reporting detection accuracy, execution time, learning time, RAM usage, and GPU memory usage. This is highly relevant to the proposed plan because it shows that baseline choice materially affects both detection performance and computational cost: MaMaDroid plus random forest achieved the best accuracy, MAPAS was about 3% lower but 76.4% faster and used about one-tenth the memory, MAPAS classified 2,000 applications in 21.18 seconds on a single CPU core, and the CNN classifier classified the same 2,000 applications in 15.92 seconds on one GPU while using 10,590 MiB of GPU memory and about 2,070 MB of RAM. The next strongest support is the iterative scientific relationship between [(Mariconti et al., 2016-12)](https://www.semanticscholar.org/paper/e8ee8fbf3a9eead394af0c8f93e02f88f7704a50) and [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3): [(Mariconti et al., 2016-12)](https://www.semanticscholar.org/paper/e8ee8fbf3a9eead394af0c8f93e02f88f7704a50) introduced MaMaDroid's API-call sequence and call-graph extraction, PCA characterization, and Markov-chain features, while [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) later re-evaluates MaMaDroid using 198,916 Markov-chain features with random forest, k-nearest neighbors, and CNN, demonstrating that the older API-call baseline remains a meaningful comparator in newer deep-learning evaluations. This supports the proposed inclusion of established sequence- and graph-based malware detectors as baselines, although the exact proposed baselines of SVM with RBF kernel, Naive Bayes with polynomial model, DeepAMD, BiGRU, and RNN-LSTM are not implemented in the supplied related work. The weakest support is from [(Mariconti et al., 2016-12)](https://www.semanticscholar.org/paper/e8ee8fbf3a9eead394af0c8f93e02f88f7704a50) itself, whose supplied text provides only section headings for detection performance, detection over time, false-positive and false-negative case studies, comparison with DroidAPIminer, and runtime performance, without quantitative accuracy, precision, recall, F1-score, runtime values, dataset size, hardware, hyperparameters, train-test splits, or statistical significance; therefore it supports the conceptual relevance of API-call-based baselines but cannot substantiate specific performance claims.

### Contradictions

The strongest contradiction or limitation is that [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) shows deep-learning baselines can be computationally expensive and not uniformly superior, which challenges the proposed assumption that a simple fixed protocol of 50 epochs and batch size 64 will yield a fair and efficient comparison. In [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3), the CNN classifier classified 2,000 applications in 15.92 seconds using one GPU but could not finish the same 2,000 applications within 24 hours without a GPU, used 10,590 MiB of GPU memory and about 2,070 MB of RAM, reported as 1,214.16% more RAM than MAPAS, and had an 11% lower detection rate than MAPAS; this indicates that deep baselines require explicit hardware, convergence, and resource reporting rather than only fixed epoch and batch settings. The next strongest contradiction is that the related work does not directly validate the proposed baseline set: [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) compares MAPAS, MaMaDroid with random forest, k-nearest neighbors, and CNN, and [(Mariconti et al., 2016-12)](https://www.semanticscholar.org/paper/e8ee8fbf3a9eead394af0c8f93e02f88f7704a50) describes MaMaDroid's Markov-chain API-call features, but neither implements SVM with RBF kernel, Naive Bayes with polynomial model, DeepAMD, BiGRU, or RNN-LSTM, so the proposed baseline comparison lacks direct empirical precedent in the supplied related work. A further limitation is input-representation mismatch: [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) uses FlowDroid-extracted API call graphs and excludes obfuscated applications whose graphs cannot be extracted, whereas the proposed plan evaluates TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020 using permissions, API calls, and high-dimensional feature vectors, so the related baselines may not be directly comparable without adaptation. The weakest contradiction is the absence of quantitative outcomes in [(Mariconti et al., 2016-12)](https://www.semanticscholar.org/paper/e8ee8fbf3a9eead394af0c8f93e02f88f7704a50); because the supplied text reports no accuracy, precision, recall, F1-score, runtime, dataset size, hardware, hyperparameters, or statistical significance, it cannot confirm that the older MaMaDroid baseline would perform well under the proposed 70/30 or 5:3:2 splits, binary and multiclass tasks, or incremental setting.

### Suggested Action

The most important action is to strengthen the baseline-comparison protocol by adding the implementation and resource details that [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) demonstrates are necessary for credible malware-detection comparisons: for SVM with RBF kernel, Naive Bayes with polynomial model, DeepAMD, BiGRU, and RNN-LSTM, report dataset preprocessing, feature dimensions, class balance, train/test/incremental splits, optimizer, learning rate, early stopping or convergence criterion, number of epochs actually used, batch size, CPU/GPU model, RAM/GPU memory, training time, inference time, and statistical significance across multiple random splits. This is critical because [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) shows that a CNN can be fast on GPU but infeasible on CPU and memory-heavy, and that accuracy differences of about 3% to 11% can coexist with large runtime and memory differences. The next most important action is to reconcile the input representation with the related API-call-graph literature: if the proposed baselines are intended to mirror [(Mariconti et al., 2016-12)](https://www.semanticscholar.org/paper/e8ee8fbf3a9eead394af0c8f93e02f88f7704a50) and [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3), the plan should extract API-call sequences or call graphs, state how obfuscated samples are handled, and report how many samples are excluded; if the plan instead uses the provided feature vectors, it should explicitly justify why MaMaDroid and MAPAS-style baselines are comparable or adapt their features to the TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020 representations. A third action is to add MaMaDroid and MAPAS, or their closest reimplementations, as additional baselines because [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) provides quantitative evidence that MaMaDroid plus random forest can outperform MAPAS in accuracy while MAPAS is faster and more memory efficient, making them useful anchors for the proposed accuracy-versus-efficiency evaluation. A fourth action is to justify the fixed 50-epoch and batch-size-64 setting with learning curves or ablations, and to report both fixed-protocol and convergence-based results, because [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) indicates that deep-model performance and cost depend strongly on hardware and training conditions. The least important but still useful action is to adopt the reporting granularity of [(Kim et al., 2022-02)](https://www.semanticscholar.org/paper/f39f1ddcee34e309501b6fb854d868ae991888a3) and address the documentation gap in [(Mariconti et al., 2016-12)](https://www.semanticscholar.org/paper/e8ee8fbf3a9eead394af0c8f93e02f88f7704a50) by specifying sample counts, feature counts, hardware, hyperparameters, and statistical tests, so that the proposed baseline comparison is reproducible and directly tied to the BID incremental-learning claim.

## Context: First primary experimental evaluation for static detection performance. Method: First, standard performance comparison experiments using 70% training and 30% testing splits to assess accuracy, precision, recall, F1-score, and computational time across both binary and multiclass classification tasks

### Support

The strongest direct support for the proposed 70/30 static comparison comes from [(Albtosh, and Omar, 2024-09)](https://www.semanticscholar.org/paper/1a342500072c381a01661d068a909db2492012c1), which evaluates a static Android malware detector, LOF KNN, on the DREBIN binary malware/benign benchmark and reports the same core classification metrics targeted by the plan: accuracy 0.9202, precision 0.8632, recall 0.8371, F1 0.8495, AUC 0.9315, false positive rate 0.367, Matthews correlation coefficient 0.7261, and true negative rate 0.632 over ten data splits. It also compares LOF KNN against Isolation Forest, supporting the plan’s broader baseline-comparison logic, although it does not provide numerical baseline values or statistical significance. This supports the plan’s choice of accuracy, precision, recall, and F1 as primary static-detection metrics, but it does not validate a 70/30 split, computational-time measurement, or multiclass behavior. A weaker but still relevant support is [(Pendlebury et al., 2018-07)](https://www.semanticscholar.org/paper/7ab5a2b7d2caa8969c06e1f24dfda2a6f5c654f6), which compares static Android malware classifiers, including a linear SVM on binary static-analysis features, a random forest on API caller-callee Markov-chain features, and a deep learning model using the same static features, and reports F1, precision, recall, and time-aware Area Under Time. Its finding that the deep learning model achieved 24-month AUT F1 0.64, compared with 0.58 for SVM and 0.32 for random forest under a realistic 10% malware prevalence and temporally consistent one-year training/two-year test protocol, supports the broader plan’s inclusion of deep baselines and the value of static feature comparison, but it supports a more rigorous evaluation than the proposed simple 70/30 comparison.

### Contradictions

The strongest contradiction is from [(Pendlebury et al., 2018-07)](https://www.semanticscholar.org/paper/7ab5a2b7d2caa8969c06e1f24dfda2a6f5c654f6), which shows that conventional random or cross-validated splits can overstate static Android malware detection performance. In biased 10-fold settings, malware F1 was approximately 0.91 for SVM and 0.97 for random forest, but under temporally consistent splits with 10% malware in training and testing, 24-month AUT F1 fell to 0.58 for SVM, 0.32 for random forest, and 0.64 for deep learning. This directly challenges the proposed first evaluation’s reliance on a standard 70/30 split if the split is random or not prevalence-matched, especially for TUANDROMD, which contains 1,000 benign and 24,553 malware samples and would produce a highly imbalanced random split unlike the 10% realistic prevalence used in the related work. A second contradiction is that [(Albtosh, and Omar, 2024-09)](https://www.semanticscholar.org/paper/1a342500072c381a01661d068a909db2492012c1), as newer 2024 work, does not address the temporal leakage concern raised by the older 2018 work, uses ten data splits without an explicit 70/30 protocol, reports a false positive rate of 0.367 and true negative rate of 0.632 while describing the false positive rate as low, and omits statistical significance, hardware specifications, computational time, and numerical Isolation Forest baseline values. This contradicts the plan’s assumption that accuracy, precision, recall, and F1 alone are sufficient for a sound static comparison. A weaker contradiction is that both related works are binary malware/goodware or benign/malware evaluations, so neither provides direct evidence that the proposed multiclass evaluation on CCCS-CIC-AndMal-2020’s 14 malware categories will behave comparably to the binary results reported in the literature.

### Suggested Action

The most important action is to redesign the 70/30 static evaluation so that it is not merely a random split: use temporally consistent train/test ordering when release dates or version metadata are available, and otherwise use prevalence-matched stratified splits that reflect realistic malware prevalence, with separate reporting for TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020 because their class ratios differ substantially. This should be accompanied by time-aware metrics such as AUT or monthly F1, precision, and recall curves, following [(Pendlebury et al., 2018-07)](https://www.semanticscholar.org/paper/7ab5a2b7d2caa8969c06e1f24dfda2a6f5c654f6), and by reporting FPR, TNR, MCC, and AUC, as in [(Albtosh, and Omar, 2024-09)](https://www.semanticscholar.org/paper/1a342500072c381a01661d068a909db2492012c1), to expose false-positive behavior that F1 may hide. The next priority is to make the computational-time claim reproducible by specifying hardware, software versions, feature extraction time, training time, inference time, and total wall-clock time for BID, SVM-RBF, Naive Bayes, DeepAMD, BiGRU, and RNN-LSTM under the same 50-epoch and batch-size-64 constraints where applicable. For multiclass tasks, report macro-averaged and weighted F1, per-class precision and recall, confusion matrices, and class imbalance handling, because the related works only support binary evaluation. Finally, add statistical significance testing or confidence intervals across multiple splits, and document hyperparameters such as LOF k-distance if anomaly baselines are used, SVM kernel parameters, and BLS/SRAE regularization terms, so that the first static comparison can serve as a valid baseline for the later 5:3:2 incremental experiments.

## Context: Second primary experimental evaluation for dynamic adaptation and efficiency. Method: Second, incremental learning experiments using a 5:3:2 ratio for training, testing, and incremental datasets to simulate real-world scenarios where new malware samples become available over time. The incremental experiments will specifically measure the system's ability to improve performance when incorporating new data without complete retraining, while also evaluating the computational efficiency gains compared to traditional retraining approaches. We will assess whether the combined time for initial training plus incremental updates is less than complete retraining time, demonstrating the practical advantages of our approach for real-time malware detection systems.

### Support

The strongest support is direct and domain-specific: [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36) implements BL-AMD, a broad learning Android malware detector that uses 379 static API, intent, and permission features, a three-layer BLS with feature, enhancement, and output nodes, sparse autoencoders, one-shot parameter computation, and incremental retraining when new samples arrive. This is the most concrete descendant of an iterative line in which [(Webb et al., 2015-11)](https://www.semanticscholar.org/paper/f28364dd4751d678a03a3448841ce01c72362732) first established a general incremental adaptation evaluation paradigm and [(Molina-Coronado et al., 2023-09)](https://www.semanticscholar.org/paper/036ec2ff218d51c8edb8726c1061b202cd245b96) later extended dynamic adaptation to Android malware retraining. BL-AMD supports the proposed BID plan because it shows that BLS-style lightweight Android malware detection can be combined with incremental updates, and its reported average scan time of about 0.2 seconds supports the feasibility of the proposed real-time efficiency goal. The next strongest support is methodological: [(Webb et al., 2015-11)](https://www.semanticscholar.org/paper/f28364dd4751d678a03a3448841ce01c72362732) evaluates incremental classifiers on 100 synthetic streams of 300,000 instances with abrupt drift at t=100,000, drift magnitudes 0, 0.25, 0.5, 0.75, and 1.0, and 0-1 error averaged over 1,000 consecutive steps, including a one-tailed binomial sign test with p=0.0001 in an extended Hoeffding Tree experiment; this supports the proposed plan's need to measure performance improvement over time and to use repeated streams and statistical tests rather than relying on a single 5:3:2 split. The weakest but still relevant support is [(Molina-Coronado et al., 2023-09)](https://www.semanticscholar.org/paper/036ec2ff218d51c8edb8726c1061b202cd245b96), which shows that Android malware detectors degrade over time and that retraining from 2013 to 2019 improves performance by 15 percent for DroidDet, 23 percent for Drebin, and 16 percent for MaMaDroid, supporting the proposed motivation that new malware samples require dynamic adaptation.

### Contradictions

The strongest contradiction to the proposed efficiency claim is that [(Molina-Coronado et al., 2023-09)](https://www.semanticscholar.org/paper/036ec2ff218d51c8edb8726c1061b202cd245b96) shows traditional retraining can be made substantially cheaper than naive periodic full retraining: Page-Hinkley change detection with threshold 0.02 reduces DroidDet retraining rounds from 28 to 8 and Drebin and MaMaDroid operations from 28 to 7 drift alarms, with only 2.3 percent average performance reduction, and selective data policies such as 45 percent labeling budgets achieve performance similar to or better than all-data retraining. This contradicts the proposed method's assumption that the combined time for initial training plus incremental updates will automatically be less than complete retraining time, because the relevant baseline may be optimized retraining with change detection and sample selection, not full retraining on all data. The next strongest contradiction is that [(Webb et al., 2015-11)](https://www.semanticscholar.org/paper/f28364dd4751d678a03a3448841ce01c72362732) finds incremental adaptation is not uniformly beneficial: under pure covariate drift, Naive Bayes, DriftDetectionMethodClassifier, DriftDetectionMethodClassifierEDDM, and AccuracyWeightedEnsemble did not return to the no-drift error level, and recovery rates were not consistently ordered by drift magnitude, so the proposed expectation that adding a 20 percent incremental malware set will improve performance may fail if the new data represent covariate drift, class imbalance, or a different malware distribution. The weakest contradiction is evidential rather than direct: [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36) reports only an average scan time of about 0.2 seconds and qualitative claims of better incremental retraining and MalGAN robustness, without accuracy, precision, recall, F1-score, statistical significance, dataset size, hardware specifications, split ratios, or a comparison of incremental update time against complete retraining, so it does not substantiate the proposed quantitative 5:3:2 efficiency and accuracy claims.

### Suggested Action

The most important action is to make the proposed computational-efficiency evaluation explicit and reproducible: for each of TUANDROMD, CIC-InvesAndMal-2019, and CCCS-CIC-AndMal-2020, report wall-clock initial training time, incremental update time per batch, total time for initial training plus all incremental updates, and complete retraining time on the combined 5:3:2 train plus incremental data, with hardware specifications, number of incremental batches, batch sizes, and mean and standard deviation over repeated runs; compare against both naive full retraining and optimized retraining baselines inspired by [(Molina-Coronado et al., 2023-09)](https://www.semanticscholar.org/paper/036ec2ff218d51c8edb8726c1061b202cd245b96), including Page-Hinkley-triggered retraining, sliding windows, and uncertainty, contrastive, or clustering-based sample selection. The next most important action is to strengthen the incremental protocol using [(Webb et al., 2015-11)](https://www.semanticscholar.org/paper/f28364dd4751d678a03a3448841ce01c72362732) by replacing a single 5:3:2 split with multiple time-ordered or random streams, several drift magnitudes, class-drift and covariate-drift conditions, learning curves over 1,000-step windows, and statistical tests such as paired bootstrap or binomial sign tests, so that performance improvement is not inferred from one split. The third action is to adopt the Android temporal evaluation details from [(Molina-Coronado et al., 2023-09)](https://www.semanticscholar.org/paper/036ec2ff218d51c8edb8726c1061b202cd245b96), such as balanced offline training, unbalanced evaluation, quarterly or time-ordered windows, labeling budgets, and TPR/TNR or F1 reporting, because the proposed 5:3:2 split may not capture the 2013-2019 style distribution shift in Android malware. The fourth action is to align the BLS implementation with [(Selvaganapathy et al., unknown_d)](https://www.semanticscholar.org/paper/5089a53019d766be2318a1496fcadd96050c7d36) by specifying the 379 static API, intent, and permission feature vector, binary encoding, feature and enhancement node counts, SRAE loss terms, sparse autoencoder hyperparameters, one-shot parameter computation, and incremental pseudo-inverse update cost, and by reporting accuracy, precision, recall, F1-score, and adversarial robustness if MalGAN-style attacks are included. The least important but still useful action is to ensure baseline fairness with SVM, Naive Bayes, DeepAMD, BiGRU, and RNN-LSTM using the stated 50 epochs and batch size 64, while also reporting training and inference time for each baseline so the proposed real-time advantage is not limited to the BID model alone.
